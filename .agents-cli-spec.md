# Agent Spec

## Overview

Build a focused tariff-monitoring prototype for Ameria Bank using Python, Google ADK, Gemini, FastAPI, PostgreSQL with pgvector, and Docker. The first supported products are consumer loans and mortgages.

The system has one ADK orchestrator with a constrained workflow. Gemini is used for language-dependent work: request intent/product resolution, bounded cache-aware source classification, and evidence-bound structured tariff extraction. Network access, document handling, OCR routing, cleaning, discovery grouping and filtering, caching, indexing, validation, persistence, change detection, HITL routing, and report formatting remain deterministic Python components.

Two entry paths invoke the same application pipeline:

- User-triggered requests through FastAPI, including imprecise Armenian or English product names.
- Scheduled monitoring every day at 06:00 Asia/Yerevan for both configured products.

The application is containerized for deployment to an AWS instance. Docker Compose runs the FastAPI service, a scheduled worker, and PostgreSQL with pgvector. AWS deployment automation is outside the native Google `agents-cli` deployment targets and will be maintained as a project-specific runtime layer.

## Example Use Cases

1. A user submits "Find the current consumer-loan tariffs for Ameria." The system resolves the product, discovers official sources, ingests and retrieves evidence, extracts and validates tariff fields, stores a snapshot, compares it with the prior snapshot, and returns a source-backed report.
2. A user enters an Armenian synonym or imprecise mortgage name. The system maps it to the configured mortgage product and follows the same pipeline.
3. The daily worker refreshes both products and records independently auditable runs.
4. A scanned PDF yields insufficient direct text. The system invokes OCR and records page-level quality metadata.
5. Two plausible official documents conflict. The system persists a human-review case containing both values and their evidence instead of silently selecting one.
6. A new normalized snapshot differs from the preceding snapshot. Formatting-only differences are ignored and meaningful changes are reported.

## Architecture

Use a modular monolith rather than a multi-agent topology:

- One ADK orchestrator exposes narrowly scoped tools and follows the constrained tariff-monitoring workflow.
- FastAPI provides user-trigger endpoints, run/status endpoints, result access, and durable HITL review endpoints.
- A separate worker process owns the daily schedule and invokes the same application service as FastAPI.
- PostgreSQL stores runs, source/document metadata, chunks, embeddings, tariff snapshots, detected changes, audit events, and HITL requests.
- pgvector and PostgreSQL full-text search provide hybrid retrieval.
- Domain services contain deterministic business logic and do not depend on the transport layer.
- Repository interfaces prevent the model from receiving SQL or unrestricted database access.

### Considered Alternatives

- Sequential specialist agents: rejected for the initial slice because additional prompts, handoffs, latency, and failure modes do not add enough value for two products.
- An ADK workflow graph: deferred because its stronger resumability does not justify the initial complexity. Durable run and HITL state will instead live in PostgreSQL.

## Tools Required

Agent-facing tools are narrow application operations, not raw infrastructure access:

- `resolve_product`: normalize Armenian/English product language and map it to a configured consumer-loan or mortgage identifier.
- `discover_official_sources`: discover and deterministically pre-filter candidate pages/documents within the configured Ameria allowlist, then rank relevance and authority.
- `ingest_source`: securely retrieve an approved HTML/PDF source; parse, OCR when required, clean, structure, chunk, and index it.
- `search_product_knowledge`: perform filtered hybrid retrieval and return evidence-bearing chunks with provenance.
- `extract_tariff_parameters`: request strict structured Gemini output using only supplied evidence; missing values must be `NOT_FOUND`.
- `validate_tariff`: apply deterministic schema, format, range, completeness, and evidence checks.
- `get_previous_snapshot`: retrieve the preceding accepted snapshot for the resolved bank/product.
- `save_snapshot`: persist a validated snapshot and its evidence through a controlled repository operation.
- `compare_tariffs`: compare canonical normalized representations and return meaningful changes only.
- `request_human_review`: persist a durable review request with reason codes and sufficient evidence.
- `build_report`: create a deterministic business-facing result containing validation status, uncertainty, evidence, and changes.

FastAPI adapters and the scheduler are application entry points, not tools available to Gemini.

## Data Sources & Authentication

- Only publicly accessible Ameria Bank pages and documents are in scope.
- Allowed hosts are explicit configuration values; the starting default is `https://ameriabank.am/`/`ameriabank.am/`, subject to validation against actual official redirects and asset hosts.
- Authentication, CAPTCHA, access-control, and anti-bot mechanisms must never be bypassed.
- Gemini uses the Developer API through `GEMINI_API_KEY`.
- Local development reads secrets from an uncommitted environment file; AWS injects them from AWS Secrets Manager or the instance runtime environment.
- The Gemini and embedding model identifiers are centralized environment settings so model choice is not spread through application code.

## Data Flow

1. FastAPI or the daily scheduler creates an auditable run.
2. Gemini converts the request into a constrained product intent.
3. Deterministic source discovery enforces scheme, host, redirect, MIME, timeout, size, grouping, reuse, and prefilter rules; only unresolved semantic classification units reach Gemini.
4. Digital content is parsed. OCR runs only when deterministic text-quality checks fall below threshold.
5. Content is cleaned while preserving page, section, table, language, and source boundaries.
6. Page-aware semantic chunks and metadata are stored and indexed in PostgreSQL/pgvector.
7. Hybrid retrieval filters by bank/product/source and combines lexical and vector relevance.
8. Gemini produces strict structured extraction with values, explicit missing states, confidence, and evidence references.
9. Deterministic validation rejects or flags malformed, implausible, incomplete, or unsupported output.
10. The normalized current snapshot is compared with the prior accepted snapshot.
11. Rule-triggered ambiguity or risk creates a durable HITL request.
12. Accepted snapshots and changes are stored and a deterministic report is returned.

## Tariff Schema

The normalized loan schema supports at least:

- Currency
- Term/duration
- Amount or amount range
- Nominal interest rate
- Effective interest rate/EIR
- Collateral/security
- Application-review fee
- Disbursement fee
- Service fee
- Salary-customer privileges

Each field carries a normalized value or explicit `NOT_FOUND`, extraction confidence/status, and evidence references including source URL, document name, page where applicable, section where available, and a bounded supporting excerpt.

## Human Review Rules

Persist a review request when at least one configured rule is met:

- Multiple similarly ranked authoritative sources remain plausible.
- Official sources provide conflicting values for the same effective context.
- OCR or document quality is below the accepted threshold.
- A critical tariff field is missing or lacks evidence.
- A change exceeds the configured absolute or relative threshold.
- Extraction fails deterministic validation after bounded retry/repair attempts.

Reviewers use FastAPI endpoints to inspect evidence and approve or reject a candidate. Decisions, actor identity supplied by the authentication boundary, timestamps, and reason/comments are retained in the audit log. Authentication/authorization for a public production deployment is required before exposing review endpoints; the local assignment interface may use a documented development-only reviewer identity.

## Constraints & Safety Rules

- The model receives no unrestricted filesystem, shell, network, database, or SQL capability.
- All outbound source URLs must use HTTPS and pass exact-host/subdomain allowlist checks before requests and after every redirect.
- Apply bounded timeouts, retry only transient failures with capped exponential backoff, and enforce configured response/PDF size and MIME limits.
- Do not fabricate missing business data. Use `NOT_FOUND` and expose uncertainty.
- Treat downloaded content as untrusted data, not executable instructions; source text cannot alter system/tool policies.
- Validate structured model output with Pydantic and deterministic domain rules.
- Sanitize logs to remove secrets, authorization headers, unnecessary document bodies, and sensitive configuration.
- Store only public source content and operational/audit data required by the assignment.
- Snapshot acceptance and high-risk changes obey HITL rules; the LLM cannot bypass them.
- The scheduler uses the `Asia/Yerevan` timezone and prevents overlapping duplicate runs for the same product/date window.
- Failures are recorded with stable reason codes and never replaced by fabricated tariff values.

## Error and Stopping Conditions

- Stop source processing on disallowed domains, redirect violations, unsupported type, excessive size, or non-public access controls.
- Stop a product run with an explicit failure if no relevant official source is found after bounded discovery.
- Invoke OCR once for low direct-text quality; route to HITL or fail if OCR remains unusable.
- Use bounded retries for transient HTTP and Gemini failures only.
- Reject invalid structured output after bounded repair attempts.
- Do not store a new accepted snapshot while required HITL approval is pending.
- A missing previous snapshot is a first-observation status, not an error or detected change.

## Observability

Use structured logs and persisted audit events with correlation identifiers for run, request, product, source, document, extraction, snapshot, and review. Record stage status, duration, retries, tool failures, retrieval scores, extraction completeness, validation failures, OCR usage/quality, HITL reason/outcome, changes, and model/token usage when exposed by the API. Never log hidden chain-of-thought.

## Success Criteria

- Consumer-loan and mortgage fixture requests resolve correctly in both Armenian and English.
- All retrieval tests prove that initial URLs and redirects outside the Ameria allowlist fail closed.
- Digital-PDF and scanned-PDF fixtures both yield page-addressable content; the scanned fixture exercises OCR fallback.
- Every accepted non-missing tariff value has a source URL and page/section evidence where the source exposes it.
- Invalid schemas, unsupported value formats, oversized downloads, and missing critical fields are rejected or routed to HITL by deterministic rules.
- Canonically equivalent values create zero changes; materially different normalized values create the expected field-level changes.
- Ambiguous documents, low OCR quality, conflicting values, missing critical evidence, and configured large-change cases create persisted HITL requests.
- Scheduled and user-triggered executions use the same pipeline and create distinct auditable run records.
- Unit/integration tests cover normalization, validation, comparison, URL controls, parsing/OCR routing, repositories, tool errors, and API boundaries.
- The initial ADK evaluation set covers both products, bilingual/imprecise intent, retrieval relevance, evidence correctness, extraction completeness, ambiguity, and controlled failures.
- `docker compose up` starts healthy FastAPI, worker, and PostgreSQL/pgvector services without embedded secrets.

## Reference Samples

- `core/python/rag-vector-search`: study custom chunking, metadata, embedding, and semantic retrieval boundaries; adapt the concepts to PostgreSQL/pgvector rather than Vertex AI Vector Search.
- `core/python/long-horizon-harness`: study durable HITL, per-tool guard chains, secret isolation, and scheduling patterns; lift only the narrow applicable interfaces.
- `core/python/ambient-expense-agent`: study headless scheduled/event-driven execution and workflow pause semantics; adapt scheduling and durable review state without adopting Pub/Sub or Google deployment infrastructure.
- `core/python/safety-plugins`: study centralized tool/model safety callbacks; use only if they strengthen the single-agent boundary without expanding scope excessively.

## Initial Scaffold Scope

The scaffold will establish package boundaries, configuration models, ADK agent entry points, FastAPI routes, worker/scheduler entry point, database migrations/models or placeholders, tool/service/repository interfaces, Docker files, test/evaluation directories, sample environment configuration, and architecture/README documentation. It will include minimal safe stubs and health checks rather than pretending the entire tariff pipeline is implemented.

## Assumptions

- Ameria Bank is the only monitored bank in the first version.
- Consumer loans and mortgages are the only initial product families.
- Public Ameria pages and documents require no authentication.
- The system uses the Gemini Developer API, not Vertex AI, and reads `GEMINI_API_KEY` from runtime configuration.
- The exact Gemini generation and embedding model IDs remain configurable and will be selected from models available to the supplied API credentials during implementation.
- PostgreSQL with pgvector is the single persistence system for structured data and retrieval indexes.
- The daily schedule is 06:00 in `Asia/Yerevan`, with on-demand API triggering also enabled.
- Initial AWS deployment means Docker Compose on one AWS compute instance; managed ECS/EKS/RDS architecture is deferred.
- A development-only reviewer identity is acceptable for local demonstration; externally exposed deployments require real authentication and authorization.
